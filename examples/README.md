# Примеры iolistgen

| Каталог | Что это | Итог проверки |
|---|---|---|
| [`kns/`](kns/README.md) | перечень вымышленной КНС-1 (проект 03): уровень, поплавки, давление, расход, три насоса с ПЧ по Modbus RTU, электроснабжение, павильон, регулятор уровня (Pid), сигналы без ФБ (роль AUX); CSV и XLSX | 58 сигналов, 30 устройств — ошибок нет |
| [`synthetic/`](synthetic/make_synthetic.py) | синтетический перечень на 300 сигналов для замера: все типы устройств, сигналов и ролей схемы | 300 сигналов, 122 устройства — ошибок нет |
| [`broken/`](broken/io_list_broken.csv) | витрина проверок: перечень с намеренными ошибками, у каждой строки — пояснение | 30 ошибок, 3 предупреждения, код выхода 1 |

Скрипты (запускаются из корня репозитория; установка пакета не обязательна — скрипты берут
`iolistgen` из клона):

| Скрипт | Что делает |
|---|---|
| [`csv_to_xlsx.py`](csv_to_xlsx.py) | перечень CSV → книга XLSX: титул, русские заголовки, числа — числами Excel; книга воспроизводима побайтно |
| [`synthetic/make_synthetic.py`](synthetic/make_synthetic.py) | синтетический перечень: `--seed` (по умолчанию 2026), `--count` (300), `--out` |
| [`benchmark.py`](benchmark.py) | замер проверки и генерации: медиана повторов, сведения о машине; отчёт — [`docs/benchmark.md`](../docs/benchmark.md) |

```bash
iolistgen validate examples/kns/io_list.csv --strict
iolistgen generate examples/kns/io_list.csv --out build/kns
python examples/synthetic/make_synthetic.py                       # пересобрать io_list_300.csv
python examples/benchmark.py                                      # замер → docs/benchmark.md
iolistgen validate examples/broken/io_list_broken.csv --report md --out docs   # docs/io_list_broken.validation.md
iolistgen validate examples/broken/io_list_broken.csv --report html --out build
```

Тесты `pytests/test_examples.py` держат примеры в согласии с валидатором: КНС и синтетический
перечень проходят проверку без сообщений, XLSX даёт ту же модель, что CSV, синтетический перечень
пересобирается из зерна побайтно, у каждой строки витрины ошибок есть ожидаемое сообщение, а отчёт
в `docs/` совпадает с текущим выводом.

## Синтетический перечень

Условная водоочистная станция из участков (насосные, реагенты, фильтры, резервуары…). Первый
участок собран по фиксированному рецепту и содержит каждый вариант, остальные — случайные
(`random.Random(seed)`), последние строки добирают точное число сигналов одиночными входами.

| Что покрыто | Варианты |
|---|---|
| AnalogInput | 4–20 мА; Modbus `REAL` (инженерные единицы, порядок слов HL и LH); Modbus `UINT`/`INT` со шкалой отсчётов в `params`; отказ канала `CHF` — DI и бит регистра |
| DigitalInput | DI; Modbus: дискретный вход (функция 2), катушка (1), бит регистра хранения (3 + `mb_bit`) |
| Motor | команда, ОС, авария, «Местное», импульс сброса |
| MotorVfd | пуск проводом + Modbus; пуск словом управления; задание AO и факт AI |
| Valve | задвижка с концевиками и муфтами; клапан с соленоидом (`SolenoidEto`, `SolenoidEtc`) |
| ControlValve | выход 4–20 мА, ОС положения отдельным AnalogInput через `link_fb`, авария позиционера |
| Сигналы без ФБ (`AUX`) | лампа на щите — простой сигнал; регистр кода аварии ПЧ — в составе насоса |

Состав `io_list_300.csv`: AI 34, AO 5, DI 140, DO 50, MB 71; устройств 122 (AnalogInput 43,
DigitalInput 38, Valve 20, MotorVfd 14, ControlValve 3, Motor 3, Pid 1). Все 22 роли схемы встречаются
хотя бы раз. Позиции тегов — номер участка · 100 + порядковый номер, поэтому `--count` — не больше
примерно 3 000 сигналов (позиции из 4 цифр, правило тегов по умолчанию).

## Витрина ошибок

[`broken/io_list_broken.csv`](broken/io_list_broken.csv) — фрагмент КНС, в котором почти каждая
строка содержит одну намеренную ошибку, а колонка «Пояснение» говорит какую (неизвестная
колонка — заодно пример предупреждения IOL005). Отчёт валидатора — [`docs/io_list_broken.validation.md`](../docs/io_list_broken.validation.md),
HTML-версия пишется в `build/` (не коммитится).

| Группа | Что сломано | Правила |
|---|---|---|
| Теги | точный дубль `LS104`; дубль без учёта регистра `ft301` / `FT301`; тег с цифры; кириллическая «Е» в `ЕS401`; `DOOR_OPEN` не по правилу именования | IOL103, IOL102, IOL104 |
| Шкала и уставки | min ≥ max; L > H; уставка HH вне шкалы; нет единиц у AI; «4,5,1» вместо числа | IOL204, IOL208, IOL209, IOL206, IOL007 |
| Modbus | `REAL` в регистрах 100–101 пересекается со словом в 101; два значения в регистре 100; один бит регистра у двух сигналов (а соседний бит — без ошибки); задание читается функцией 3; `REAL` пишется функцией 6; бит 16; нет порядка слов; слейв 250 | IOL412, IOL410, IOL405, IOL407, IOL408, IOL414 |
| Устройства | ПЧ без задания частоты; задвижка без «Закрыть»; ОС «в работе» аналоговым сигналом; тип устройства `Mixer`; тип сигнала `DIO`; повтор `dev_no`; `link_power` на несуществующее устройство; два сигнала на канале модуля; нет описания | IOL308, IOL312, IOL306, IOL301, IOL202, IOL311, IOL313, IOL601, IOL201 |
| Параметры Cfg | опечатка `tMinStopp` (с подсказкой `tMinStop`); `uiMaxStartsPerHour=-1`; гистерезис шире шкалы и `UINT` без шкалы отсчётов — конфигурации, которые отклонил бы `CheckConfig` ФБ | IOL502, IOL503, IOL507 |
