# Генераторы и плагины

Генератор превращает проверенный перечень (`iolistgen.model.IoList`) в файлы: исходники ST,
карты обмена Modbus, импорт тегов SCADA, таблицы документации. Встроенные генераторы живут в
пакете (`iolistgen/generators/`): `st-codesys`, `modbus-map`, `scada-csv`, `alarm-list`,
`docs-table` (форматы и опции — [GENERATORS.md](GENERATORS.md)). Сторонние подключаются
плагинами — пакетами Python с точкой входа. Короткий образец — `docs-table`, пример отдельного
пакета-плагина — [`plugins/iolistgen-masterscada4d/`](../plugins/iolistgen-masterscada4d/README.md).

## Протокол

```python
from collections.abc import Sequence
from pathlib import Path

from iolistgen.generators import GeneratorContext, GeneratorOption
from iolistgen.model import IoList


class MyGenerator:
    name = "wincc-csv"  # строчные латинские буквы, цифры, дефис
    description = "импорт тегов в SCADA (CSV)"
    options: Sequence[GeneratorOption] = (
        GeneratorOption("filename", "имя файла", "str", "scada_tags.csv"),
        GeneratorOption("delimiter", "разделитель", "choice", ";", (";", ",")),
        GeneratorOption("with_alarms", "добавить теги тревог", "bool", True),
    )

    def generate(self, model: IoList, out_dir: Path, ctx: GeneratorContext) -> list[Path]:
        sep = ctx.str_option("delimiter")
        lines = [ctx.comment_header("hash").rstrip("\n"), sep.join(("tag", "description", "units"))]
        for signal in model.signals:
            lines.append(sep.join((signal.ident, signal.description, signal.units or "")))
        return [ctx.write_text(ctx.str_option("filename"), "\n".join(lines) + "\n")]
```

Протокол `iolistgen.generators.Generator` проверяется при загрузке: у объекта есть `name`,
`description`, `options` и метод `generate(model, out_dir, ctx) -> list[Path]`.

**Опции** — `GeneratorOption(name, help, kind, default, choices)`, вид `str`, `bool`, `int`
или `choice`. Значения берутся по слоям: умолчание ← `[generators.<имя>]` в `iolistgen.toml` ←
`--set <имя>.<опция>=<значение>`; неизвестная опция или неверное значение — код выхода 2.

**Контекст** `GeneratorContext`:

| Член | Назначение |
|---|---|
| `option()`, `str_option()`, `bool_option()`, `int_option()` | значения опций |
| `write_text(путь, текст)` | файл внутри `out_dir`: UTF-8 без BOM, переводы строк LF, перезаписывается только при изменении; путь вне каталога вывода — `ValueError`. Команда `iolistgen generate` создаёт контекст с отложенной записью (`deferred`): файлы пишутся вызовом `commit()` после того, как все генераторы отработали без ошибок, — генератор не должен читать свои же файлы с диска после `write_text` |
| `outputs` | файлы генератора и признак «изменён» (их печатает команда) |
| `comment_header("st" \| "markdown" \| "hash")` | заголовок «AUTO-GENERATED by iolistgen <версия> — не редактировать; источник: <перечень>» и строка с SHA-256 перечня и именем генератора |
| `config`, `source`, `version` | настройки проекта, сведения о файле перечня, версия iolistgen |
| `warn(текст)`, `warnings` | предупреждения генератора — команда печатает их перед списком файлов; с `--strict` предупреждение отменяет запись всех файлов |
| `timestamp` | время генерации, если задан `--timestamp` (уже входит в заголовок) |

Генерация должна быть идемпотентной: никаких дат и случайных значений в выводе, порядок —
детерминированный (файл, `dev_no`, имя). Тогда повторный запуск ничего не меняет, а дифф в
pull request показывает только реальные изменения перечня.

## Что даёт модель

```python
from iolistgen.enums import Role

for device in model.devices_by_dev_no():  # порядок GVL_Persist (контракт 20.6)
    spec = device.spec  # ФБ, Cmd, Cfg, Sts, слоты тревог, роли
    print(f"fb{device.ident} : PL.{spec.fb};")
    init = device.cfg.initializer()  # "" — все поля по умолчанию
    print(f"st{device.ident}Cfg : PL.{spec.cfg}{' := ' + init if init else ''};")
    for slot in spec.alarm_slots:  # код тревоги и номер
        print(f"{device.ident}.{slot.suffix}", device.alarm_id_base + slot.index)
    main = device.main  # главная строка
    run_fb = device.signal(Role.RUN_FB)  # сигнал роли или None
    if device.link_power:  # идентификатор DI-устройства «напряжение»
        print(f"xPowerOk := GVL_Devices.fb{device.link_power}.xValue")
```

- Сигнал без ФБ (роль `AUX`): `signal.is_aux`; у простого сигнала без устройства
  `signal.device is None` — генератор, который ищет устройство сигнала, проверяет это
  (`model.plain_signals()` — все такие сигналы). Сигналы AUX устройства лежат в
  `device.signals`, но входа ФБ у них нет.
- `Device.cfg.values` — все скалярные поля DUT с типом ST, значением, умолчанием и
  происхождением (`default`, `column`, `params`, `inferred`) — для комментариев «откуда
  значение». `cfg.initializer()` пишет только изменённые поля и массивы целиком (18.3, правило 3).
- `Signal.modbus` — адрес PDU с нуля (`address`), пространство (`space.prefix`: 0x, 1x, 3x,
  4x), функция, тип и длина, бит, порядок слов (по умолчанию уже подставлен), слейв и линия.
- `Signal.ident` — идентификатор ST из тега; префиксы типа (`x`, `r`) добавляет генератор.

**Имена ПЛК** — `iolistgen.generators.plc.build_plc(model)`: те же имена, что пишет `st-codesys`.
Плагину для SCADA или документации не нужно повторять правила имён:

```python
from iolistgen.generators.plc import build_plc

plc = build_plc(model)
for binding in plc.by_dev_no():  # экземпляр, Cmd, Cfg, Retain, параметры вызова
    print(binding.instance_path, binding.cmd_path, binding.cfg_path)
for var in plc.io_vars:  # переменные GVL_IO: имя, тип, раздел, комментарий привязки
    print(var.path, var.st_type, var.section)
print(plc.signal_var(model.signals[0]).path)  # GVL_IO.rLT101_mA
```

Ошибку, которую пользователь должен исправить в перечне или опциях, генератор сообщает
исключением `GenerationError` (команда печатает текст и выходит с кодом 1), предупреждение —
`ctx.warn("…")`.

Подробно — [schema.md](schema.md), раздел 12.

## Регистрация

**Встроенный генератор** — класс в `iolistgen/generators/` и строка в
`registry.builtin_generators()`.

**Плагин** — отдельный пакет с точкой входа в группе `iolistgen.generators`:

```toml
# pyproject.toml пакета-плагина
[project]
name = "iolistgen-wincc-csv"
dependencies = ["iolistgen>=0.1"]

[project.entry-points."iolistgen.generators"]
wincc-csv = "iolistgen_wincc_csv:MyGenerator"
```

После `pip install` (или `pipx inject iolistgen iolistgen-wincc-csv`) генератор появляется в
`iolistgen generate --list`. Объект точки входа — класс (создаётся без аргументов) или готовый
экземпляр; имя точки входа совпадает с `name` генератора. Встроенные имена заняты: плагин с
таким же именем не загружается.

**Ошибки плагинов** не ломают остальные генераторы: плагин, который не импортировался или не
соответствует протоколу, показывается в `--list` с причиной и пропускается (если его не
запросили явно через `--only` — тогда код выхода 2). Исключение внутри `generate()` — сообщение
и код выхода 1.

## Тесты генератора

- Проверяйте вывод на фиксированном перечне — эталонными файлами, как встроенные генераторы
  (`pytests/test_golden.py`, `pytests/golden/`), или проверкой ключевых строк
  (`pytests/test_generators.py`).
- Повторный запуск не меняет файлы: `ctx.outputs[i].changed is False`.
- Плагины в тестах подставляются через `importlib.metadata.entry_points` (см.
  `test_entry_point_plugins`).
