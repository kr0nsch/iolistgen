# Командная строка и настройки

## Установка

Нужен Python 3.10+. CODESYS для проверки и генерации не нужен.

```bash
pipx install .                 # из корня репозитория: команда iolistgen в изолированном окружении
# или для разработки:
python -m pip install -e .     # пакет в режиме редактирования
python -m pip install -r requirements-dev.txt   # ruff, mypy, pytest, hypothesis — для тестов и CI
```

Без установки: `python -m iolistgen ...` из корня репозитория.

## Команды

### `iolistgen validate` — проверка перечня

```text
iolistgen validate ПЕРЕЧЕНЬ [--config ФАЙЛ | --no-config] [--sheet ЛИСТ] [--encoding КОДИРОВКА]
                   [--report md|html|both] [--out КАТАЛОГ] [--format text|json] [-q] [--strict]
```

| Параметр | Что делает |
|---|---|
| `ПЕРЕЧЕНЬ` | файл `.csv` или `.xlsx` (`.xlsm`) |
| `--config ФАЙЛ` | файл настроек; без него `iolistgen.toml` ищется рядом с перечнем и выше, до корня репозитория (каталог с `.git`) |
| `--no-config` | не искать `iolistgen.toml`: только значения по умолчанию |
| `--sheet ЛИСТ` | лист книги XLSX (по умолчанию — первый лист со строкой заголовка) |
| `--encoding КОДИРОВКА` | кодировка CSV, перекрывает `[input] encoding` |
| `--report md\|html\|both` | записать отчёт `<имя перечня>.validation.md` / `.html` |
| `--out КАТАЛОГ` | каталог отчётов (по умолчанию текущий) |
| `--format json` | вывод в консоль в JSON (для CI и редакторов) |
| `-q`, `--quiet` | только итоговая строка |
| `--strict` | предупреждения тоже дают код выхода 1 |

Пример вывода:

```text
$ iolistgen validate pytests/data/kns_errors.csv
pytests/data/kns_errors.csv:2: IOL204 [ошибка] колонка H «range_min»: диапазон 5…0: минимум не меньше максимума (см. колонку I «range_max»)
    как исправить: задайте range_min меньше range_max (иначе ФБ отклонит Cfg: AI_CFG_RANGE)
...
pytests/data/kns_errors.csv: 16 сигналов, 9 устройств — 12 ошибок, 3 предупреждения
```

Формат строки сообщения: `файл:строка: КОД [уровень] лист, колонка «заголовок»: что не так`,
следующая строка — как исправить. Так файл и строку понимают редакторы и журналы CI.

**JSON** (`--format json`): объект с полями `file`, `sheet`, `sha256`, `config`, `ok`, `errors`,
`warnings`, `stats` (`signals`, `devices`, `modbus`, `by_signal_type`, `by_device_type`),
`reports` и `diagnostics` — список сообщений (`code`, `severity`, `message`, `hint`, `source`
с `file`, `sheet`, `row`, `col`, `header`, `related`, `tag`, `device`).

### `iolistgen generate` — генерация

```text
iolistgen generate ПЕРЕЧЕНЬ --out КАТАЛОГ [--only ИМЯ,...] [--set ГЕНЕРАТОР.ОПЦИЯ=ЗНАЧЕНИЕ]...
                   [--config ФАЙЛ | --no-config] [--sheet ЛИСТ] [--encoding КОДИРОВКА] [--strict]
                   [--timestamp]
iolistgen generate --list
```

Перед генерацией перечень проверяется: при ошибках (с `--strict` — и при предупреждениях)
файлы не пишутся, код выхода 1. Без `--only` запускаются все доступные генераторы.

Генерация выполняется целиком или не выполняется: генераторы работают в памяти, и файлы
пишутся, только если все отработали без ошибок, а с `--strict` — и без предупреждений
(например, сверки `GVL_Persist`: «тип изменился», «переменная удалена»). Сбой одного генератора
или плагина не оставляет в проекте новый ST рядом со старыми картами обмена. Два генератора,
которые пишут один файл, — ошибка до записи.

Файл перезаписывается, только если содержимое изменилось: повторная генерация из того же
перечня ничего не меняет и не трогает время изменения файлов. SHA-256 перечня в заголовках
считается по содержимому таблицы, поэтому пересохранение книги Excel без правок тоже ничего не
меняет. Времени генерации в файлах нет; `--timestamp` добавляет его в заголовки (тогда каждый
запуск меняет все файлы).

Встроенные генераторы — `st-codesys`, `modbus-map`, `scada-csv`, `alarm-list`, `docs-table`;
с `--out .` (корень проекта) ST ложится в `src/GVLs/Generated/` и `src/POUs/Generated/`,
карты Modbus, список тревог и перечень — в `docs/`, импорт SCADA — в `scada/`. Файлы, форматы
и опции — [GENERATORS.md](GENERATORS.md). Предупреждения генераторов (например, сверка
`GVL_Persist`) печатаются перед списком файлов; ошибка генератора (конфликт имён в `GVL_IO`) —
сообщение, код выхода 1, файлы не записаны.

Опции генератора берутся по слоям: значение по умолчанию ← `[generators.<имя>]` в
`iolistgen.toml` ← `--set <имя>.<опция>=<значение>`. Опции-пути (`st-codesys.persist_extra`,
`alarm-list.templates`, `scada-csv.templates`): относительный путь из `iolistgen.toml` — от каталога
файла настроек, из `--set` — от текущего каталога. Список генераторов, их опций и плагинов,
которые не загрузились (с причиной), — `iolistgen generate --list`:

```text
Генераторы iolistgen (плагины — точки входа iolistgen.generators):
  st-codesys  встроенный — ST для CODESYS: GVL_IO, GVL_Devices, GVL_Hmi, GVL_Persist, GVL_CfgProject, PRG_Devices
                src_dir = src: каталог раскладки ST относительно --out
                folder = Generated: папка проекта CODESYS для сгенерированных объектов (пусто — без папки)
                ...
  docs-table  встроенный — таблица «Перечень сигналов» для docs/ (Markdown)
                filename = docs/signal_list.md: имя файла относительно --out
                title = Перечень сигналов: заголовок документа
                group_by_device = true: таблица сигналов по разделам устройств
                plc_variables = true: колонка «Переменная ПЛК» (GVL_IO)
```

### `iolistgen schema` — справочник схемы

```text
iolistgen schema [--format md|json] [--section РАЗДЕЛ]... [--output ФАЙЛ]
```

Разделы: `columns`, `device-types`, `roles`, `links`, `alarms`, `params`, `modbus`, `rules`.
Справочник строится из тех же каталогов, что и проверка; подробное описание с примерами —
[schema.md](schema.md). `--output` пишет файл в UTF-8 (в консоли Windows вывод в файл через `>`
зависит от кодировки консоли).

## Коды выхода

| Код | Когда |
|---|---|
| 0 | ошибок нет (предупреждения допустимы без `--strict`) |
| 1 | в перечне есть ошибки; с `--strict` — и предупреждения перечня или генераторов; генератор завершился ошибкой |
| 2 | неверные аргументы; ошибка в `iolistgen.toml` (в том числе попытка ослабить структурное правило); файла нет, это каталог или формат не `.csv`/`.xlsx` |

## Отчёты

`--report md` — Markdown для pull request и `docs/`: шапка (файл, SHA-256, настройки — путь к
`iolistgen.toml` относительно каталога перечня, версия),
итог, сводка, таблица сообщений «уровень, код, строка, колонка, тег, что не так, как
исправить» и сработавшие правила. `--report html` — один HTML-файл без внешних ресурсов:
светлая и тёмная тема по настройке системы, фильтр «ошибки/предупреждения» и поиск по тегу и
тексту, печать без элементов управления. Время прогона в отчёт не пишется — только SHA-256
содержимого перечня, поэтому повторная проверка того же перечня даёт побайтно тот же отчёт.

## Файл настроек `iolistgen.toml`

Пример со всеми параметрами — [iolistgen.example.toml](iolistgen.example.toml). Неизвестный
параметр, неверное значение или регулярное выражение — ошибка с кодом выхода 2.

| Параметр | По умолчанию | Что задаёт |
|---|---|---|
| `[naming] tag_regex` | `^[A-Z]{1,4}[0-9]{1,4}[A-Z]?(_[A-Z0-9]+)*$` | правило тегов (IOL104); сверить с проектным стандартом |
| `[naming] device_regex` | `^[A-Z]{1,4}[0-9]{1,4}[A-Z]?$` | правило имён устройств из колонки `device` (IOL106) |
| `[naming] max_device_length` | 24 | предел длины имени устройства (IOL107) |
| `[modbus] address_base` | 0 | 0 — адреса PDU с нуля; 1 — нумерация с единицы |
| `[modbus] default_word_order` | не задан | порядок слов 32/64-битных значений без `mb_order`: `HL` или `LH` |
| `[input] sheet` | первый лист с заголовком | лист XLSX |
| `[input] encoding` | `utf-8` | кодировка CSV |
| `[input] delimiter` | по заголовку | разделитель CSV: `;`, `,`, `\t` |
| `[input] ignore_columns` | `[]` | колонки, которые не читаются (без IOL005) |
| `[input] column_aliases` | `{}` | свои заголовки: `{ "Позиция по схеме" = "tag" }` |
| `[input] header_search_rows` | 30 | сколько строк сверху просматривать в поисках заголовка |
| `[severity] IOLxxx` | уровень правила | `"error"`, `"warning"` или `"off"`; структурные правила (в справочнике правил — «Ослабить: нет») понизить нельзя — без их данных модель перечня не строится |
| `[generators.<имя>] <опция>` | умолчание генератора | опции генераторов |

## Разработка

```bash
python -m ruff check . && python -m ruff format --check .
python -m mypy                      # strict: пакет, тесты, инструменты шаблона
python -m pytest pytests            # тесты пакета (pytest tools/tests — инструменты шаблона)
python -m iolistgen.schema_doc docs/schema.md   # обновить справочник в docs/schema.md
```
