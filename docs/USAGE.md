# Свой перечень: от таблицы до проекта CODESYS

Как описать перечень сигналов своего объекта в CSV или Excel, проверить его, прочитать отчёт,
сгенерировать код и карты и подключить сгенерированный ST к проекту CODESYS из шаблона
[plc-repo-template](https://github.com/kr0nsch/plc-repo-template). Короткая версия —
[README](../README.md#как-использовать-в-своём-проекте). Полный справочник колонок, ролей,
параметров и правил — [schema.md](schema.md), ключи команд — [CLI.md](CLI.md), файлы и опции
генераторов — [GENERATORS.md](GENERATORS.md), шаги в IDE — [MANUAL_STEPS.md, раздел 9](MANUAL_STEPS.md#9-код-сгенерированный-iolistgen-в-проекте-codesys).

Команды — из корня проекта; в cmd, PowerShell и bash они пишутся одинаково. Что проверено, а что
нет, отмечено в каждом разделе: команды iolistgen и проверки шаблона без CODESYS выполнены
19.10.2026 в чистом клоне plc-repo-template; шаги в CODESYS повторяют порядок, по которому собран
пример КНС-1 в этом репозитории, — в проекте из шаблона они не запускались.

## 1. Что правится руками, а что генерируется

| Файл | Кто пишет | Править вручную |
|---|---|---|
| `docs/io_list.csv` или `.xlsx` (имя и место — любые) | инженер | да — единственный источник |
| `iolistgen.toml` рядом с перечнем или выше, до корня репозитория | инженер | да: правила имён, свои заголовки колонок, уровни правил, опции генераторов ([пример](iolistgen.example.toml)) |
| `src/GVLs/Generated/`, `src/POUs/Generated/` | `iolistgen generate` | нет: ошибка в коде исправляется в перечне, настройках или шаблоне генератора |
| `docs/modbus_master_map.csv`, `docs/modbus_slave_map.csv`, `docs/modbus_map.md`, `docs/alarms.csv`, `docs/signal_list.md`, `scada/scada_tags.csv`, `scada/scada_alarms.csv` | `iolistgen generate` | нет |
| `PRG_Main`, логика станции, вызовы ПИД-регуляторов, адаптеры ПЧ, слой Modbus | инженер | да — вне папок `Generated` |
| `tools/codesys/config.json` | инженер | да: библиотека plc-process-lib, задачи |

Каждый сгенерированный файл начинается со строки `AUTO-GENERATED by iolistgen <версия> — не
редактировать; источник: <файл перечня>` и SHA-256 содержимого перечня.

## 2. С чего начать перечень

**Взять за основу пример.** В строке заголовка [`examples/kns/io_list.csv`](../examples/kns/io_list.csv)
есть все 31 колонка схемы: скопируйте файл в проект, оставьте заголовок и впишите свои строки.
Ненужные колонки можно удалить, обязательны только пять: `tag`, `description`, `signal_type`,
`device_type`, `dev_no`. Для Excel — [`examples/kns/io_list.xlsx`](../examples/kns/io_list.xlsx): те же
колонки с русскими заголовками («Тег», «Тип сигнала»), титул над таблицей, числа — числами Excel.

**CSV.** UTF-8 (BOM допускается), разделитель `;`, `,` или табуляция — определяется по строке
заголовка, поэтому десятичная запятая в данных не мешает. Ячейку `params` с `;` берите в кавычки
(в последней колонке iolistgen склеит её и без кавычек). Обычный CSV из Excel в русской Windows
сохраняется в cp1251 — проверка ответит так:

```text
docs/io_list.csv:2: IOL001 [ошибка] файл не в кодировке utf-8: байт 0xD3 в строке 2
    как исправить: сохраните перечень как «CSV UTF-8» (в Excel: «Сохранить как», тип «CSV UTF-8») или укажите кодировку: --encoding cp1251
```

С `--encoding cp1251` (или `[input] encoding = "cp1251"` в `iolistgen.toml`) тот же файл читается.

**XLSX.** Читается первый лист, где есть строка заголовка (или `--sheet`); строки над заголовком —
титул, не читаются. Объединённые по вертикали ячейки («Устройство» на все строки насоса) действуют
в каждой строке, строка-подзаголовок, объединённая через всю таблицу, пропускается, строка с первой
непустой ячейкой на `#` — комментарий. Значения формул берутся сохранённые: книгу, записанную программой и не
открытую в Excel, iolistgen не пересчитывает, а сообщает о формулах без значения (IOL007).

**Свои заголовки.** Русские названия и синонимы распознаются сами («Задержка вкл., с» = `delay_on_s`,
«Адрес регистра (PDU)» = `mb_reg`; список — `iolistgen schema --section columns`). Другие — в
`iolistgen.toml`:

```toml
[input]
column_aliases = { "Позиция по схеме" = "tag", "Наименование параметра" = "description" }
ignore_columns = ["№ п/п", "Примечание"]
```

**CSV → Excel.** Скрипт из клона iolistgen собирает книгу с титулом и русскими заголовками:
`python examples/csv_to_xlsx.py <путь>/io_list.csv <путь>/io_list.xlsx --title "Объект. Перечень сигналов"`
(проверено на перечне из пяти строк: книга даёт ту же проверку, что CSV).

## 3. Колонки: шпаргалка

★ — колонка должна быть в заголовке. «Главная строка» — строка устройства с главной ролью
(раздел 4): свойства устройства читаются из неё. Полное описание с синонимами и допустимыми
значениями — [schema.md, раздел 2](schema.md#2-колонки).

| Группа | Колонки | Где | Что писать |
|---|---|---|---|
| Сигнал | `tag` ★, `description` ★, `signal_type` ★ | каждая строка | тег (латиница, цифры, `_`; из него — имя переменной), описание, тип: AI, DI, DO, AO или MB (значение по Modbus) |
| Устройство | `device`, `device_type` ★, `dev_no` ★, `dev_desc` | `device` — каждая строка устройства; остальное — главная строка | тег устройства (пусто — устройство из одной строки с именем `tag`), тип ФБ, постоянный номер 1…9999, название для HMI и тревог |
| Привязка | `role` | каждая строка | вход или выход ФБ (раздел 4); у AI и DI по умолчанию `PV` и `IN`; `AUX` — сигнал без ФБ |
| Шкала | `range_min`, `range_max`, `units` | строка аналогового сигнала | границы шкалы в инженерных единицах и единицы; у `AnalogInput` обязательны |
| Уставки и тревоги | `sp_hh`, `sp_h`, `sp_l`, `sp_ll`, `delay_on_s`, `delay_off_s`, `alarm_priority` | главная строка | LL < L < H < HH внутри шкалы; задержки — `3`, `0,5`, `500 мс`, `T#2S`; куда идёт задержка — по типу устройства; приоритет None, Low, Medium, High, Critical |
| Канал модуля | `io_module`, `io_channel` | строка AI, DI, DO, AO | имя модуля и номер канала: попадают в комментарий `GVL_IO` и перечень, по ним ищутся два сигнала на одном канале; адресов `AT` в коде нет |
| Modbus | `mb_link`, `mb_slave`, `mb_func`, `mb_reg`, `mb_type`, `mb_bit`, `mb_order` | строка MB | линия (RS-485 или TCP), адрес слейва, функция 1–6, 15, 16, адрес PDU с нуля, тип данных, бит регистра для BOOL, порядок слов HL или LH для 32/64 бит |
| Связи | `link_power`, `link_fb` | главная строка | тег DI-устройства «питание в норме» (Motor, MotorVfd, Valve); тег AI-устройства ОС положения (ControlValve) |
| Настройки ФБ | `params` | главная строка | `<поле>=<литерал ST>; …` — любые поля структуры настроек ФБ: `tMinStop=T#30S; stVfd.rSpeedMin_pct=60.0`; поля по типам — [schema.md, раздел 8](schema.md#8-параметры-cfg-колонка-params) |
| HMI | `hmi_group` | каждая строка | группа экрана HMI или SCADA |

Числа понимаются в привычной записи: `4,5` и `4.5`, `1 000`, минус «−» из паспорта прибора;
ячейка из одного тире — «нет значения». Значения из списков (тип сигнала, роль, тип устройства) —
без учёта регистра, с пояснением после значения («AI 4–20 мА»).

## 4. Устройства и роли

Строки с одинаковым `device` — одно устройство, один экземпляр ФБ `fb<DEV>`. Тип, номер, уставки,
связи и `params` пишутся в главной строке; в остальных строках устройства `device_type` и `dev_no`
можно не заполнять (а если заполнены — значения должны совпадать).

| Тип устройства | ФБ | Главная строка | Другие роли |
|---|---|---|---|
| `AnalogInput` | `PL.FB_AnalogInput` | `PV` — AI или MB | `CHF` — отказ канала |
| `DigitalInput` | `PL.FB_DigitalInput` | `IN` — DI или MB | `CHF` |
| `Motor` | `PL.FB_Motor` | `CMD_RUN` — DO | `RUN_FB`, `FAULT`, `LOCAL`, `CMD_RESET` |
| `MotorVfd` | `PL.FB_MotorVfd` | `CMD_RUN` — DO или `VFD_CTW` — MB | обязательно `VFD_STW`, `SPEED_REF`, `SPEED_ACT`; `RUN_FB`, `FAULT`, `LOCAL`, `CMD_RESET` |
| `Valve` | `PL.FB_Valve` | `CMD_OPEN` или `CMD_COIL` — DO | `CMD_CLOSE`, `ZSO`, `ZSC`, `TQO`, `TQC`, `FAULT`, `LOCAL` |
| `ControlValve` | `PL.FB_ControlValve` | `POS_OUT` — AO | `POS_FAULT`, `LOCAL`; ОС положения — отдельный `AnalogInput` через `link_fb` |
| `Pid` | `PL.FB_PID` | строка устройства без `signal_type` и `role`; диапазон PV — `range_min`, `range_max` | — (вызов и привязки пишет логика станции) |
| любой или без устройства | — | — | `AUX` — сигнал без ФБ: лампа, сирена, резерв, регистр, который читает код приложения |

Какой роли какой вход или выход ФБ и какие типы данных Modbus допустимы — `iolistgen schema
--section roles` и [schema.md, раздел 4](schema.md#4-роли-сигналов).

**`dev_no` — постоянный номер.** От него зависят номера тревог (`dev_no · 10 + слот`), порядок
`GVL_Persist` и индексы `GVL_DevIdx`. После пуска объекта номера не меняют, новому устройству дают
номер больше прежних: тогда его данные встают в конец сохраняемой области, а сохранённые уставки
остальных устройств не теряются.

Пример из трёх устройств — уровнемер, реле контроля фаз, вентилятор — разобран в
[README](../README.md#как-использовать-в-своём-проекте).

## 5. Пример: насос с ПЧ по Modbus

Строки насоса Н1 из перечня КНС-1 ([examples/kns/io_list.csv](../examples/kns/io_list.csv)); пустые
колонки опущены, колонка `io` здесь — `io_module`.`io_channel`, у строк MB во всех строках
`mb_link` = `RS485-1`:

| tag | signal_type | device | device_type | dev_no | role | io | mb_slave | mb_func | mb_reg | mb_type | link_power | params |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| P101_RUN | DO | P101 | MotorVfd | 11 | CMD_RUN | Q1.1 | | | | | ES301 | `tMinStop=T#30S; uiMaxStartsPerHour=10; stVfd.rSpeedMin_pct=60.0; …` |
| P101_RFB | DI | P101 | | | RUN_FB | D2.1 | | | | | | |
| P101_FLT | DI | P101 | | | FAULT | D2.2 | | | | | | |
| HS114 | DI | P101 | | | LOCAL | D2.3 | | | | | | |
| P101_CTW | MB | P101 | | | VFD_CTW | | 1 | 16 | 0 | WORD | | |
| P101_FREF | MB | P101 | | | SPEED_REF | | 1 | 16 | 1 | UINT | | |
| P101_STW | MB | P101 | | | VFD_STW | | 1 | 3 | 100 | WORD | | |
| P101_FACT | MB | P101 | | | SPEED_ACT | | 1 | 3 | 101 | UINT | | |
| P101_FCODE | MB | P101 | | | AUX | | 1 | 3 | 103 | UINT | | |

`iolistgen generate` даёт в `PRG_Devices` вызов со всеми привязками, а в `GVL_Persist` — настройки
с задержками из колонок (`delay_on_s` = 10, `delay_off_s` = 15 → `tFbStart`, `tFbStop`) и полями из
`params`, номер первой тревоги `dev_no · 10` и Retain устройства:

```st
// --- dev_no 11: P101 — Насос Н1 (MotorVfd) ---
// ПЧ: xCommOk, xVfd*, rSpeedAct_pct и rSpeedRef_pct — через адаптер приложения (GVL_IO.xP101_…)
// без входа ФБ (AUX, код приложения): GVL_IO.uiP101_FCODE — Насос Н1: код последней аварии ПЧ (читает адаптер ПЧ)
GVL_Devices.fbP101(
    xFbRun        := GVL_IO.xP101_RFB,
    xExtFault     := GVL_IO.xP101_FLT,
    xLocal        := GVL_IO.xHS114,
    xPowerOk      := GVL_Devices.fbES301.xValue,  // link_power
    xCommOk       := GVL_IO.xP101_CommOk,
    xVfdRunning   := GVL_IO.xP101_VfdRun,
    xVfdReady     := GVL_IO.xP101_VfdReady,
    xVfdFault     := GVL_IO.xP101_VfdFault,
    rSpeedAct_pct := GVL_IO.rP101_SpeedAct_pct,
    stCmd         := GVL_Hmi.stP101Cmd,
    stCfg         := GVL_Persist.stP101Cfg,
    stRetain      := GVL_Persist.stP101Retain);
GVL_IO.xP101_RUN          := GVL_Devices.fbP101.xQRun;
GVL_IO.xP101_VfdQRun      := GVL_Devices.fbP101.xQRun;
GVL_IO.xP101_VfdQReset    := GVL_Devices.fbP101.xQReset;
GVL_IO.rP101_SpeedRef_pct := GVL_Devices.fbP101.rSpeedRef_pct;

// GVL_Persist.pvl.st (VAR_GLOBAL PERSISTENT RETAIN), по возрастанию dev_no
    stP101Cfg : PL.ST_MotorCfg := (
        tFbStart := T#10S,
        tFbStop := T#15S,
        tMinStop := T#30S,
        uiMaxStartsPerHour := 10,
        stVfd := (
            rSpeedMin_pct := 60.0,
            rRampUp_pctps := 5.0,
            rRampDown_pctps := 5.0,
            xFbFromComm := FALSE,
            xCommLossIsFault := FALSE
        ),
        udiAlarmIdBase := 110
    );
    stP101Retain : PL.ST_DeviceRetain;  // режим, вывод из работы, наработка, операции
```

Слово состояния и задание частоты ПЧ разбирает адаптер приложения (`GVL_IO.wP101_STW` →
`xP101_VfdRun`…): карта регистров у каждой модели ПЧ своя, в КНС-1 она условная. Регистры ПЧ
попадают в карту обмена `docs/modbus_master_map.csv` — с функцией, адресом, типом и переменной ПЛК:

```text
link;slave;function;function_name;area;address;bit;length;data_type;word_order;direction;tag;description;device;role;plc_variable;eng_min;eng_max;units;raw_min;raw_max;scaling
RS485-1;1;16;Write Multiple Registers;4x;0;;1;WORD;;запись;P101_CTW;Насос Н1: слово управления ПЧ;P101;VFD_CTW;GVL_IO.wP101_CTW;;;;;;биты слова — разбирает и собирает адаптер ПЧ (код приложения)
```

Без строки `SPEED_REF` перечень не пройдёт проверку (IOL308): ФБ ПЧ без задания скорости не
работает. Другие типовые устройства — задвижка, клапан с соленоидом, регулирующий клапан, датчик
по Modbus, ПИД-регулятор, сигналы без ФБ — [schema.md, раздел 10](schema.md#10-примеры).

## 6. Проверка и отчёт

```bash
iolistgen validate docs/io_list.csv                                  # консоль
iolistgen validate docs/io_list.csv --report html --out build/reports # и HTML-отчёт
iolistgen validate docs/io_list.xlsx --sheet Перечень --strict       # лист книги; предупреждения — тоже ошибка
```

**Формат сообщения:** `файл:строка: КОД [уровень] колонка «заголовок»: что не так`, на следующей
строке — `как исправить`. Пример — опечатка в `params` и два сигнала на одном канале:

```text
docs/io_list.csv:4: IOL502 [ошибка] колонка AE «params»: params: нет поля «tMinStopp» в ST_MotorCfg
    как исправить: возможно, tMinStop
docs/io_list.csv:5: IOL601 [ошибка] колонка U «io_channel»: канал DI 4 модуля D1 уже занят сигналом ES301 (см. строку 3)
    как исправить: у каждого физического канала один сигнал: проверьте io_module и io_channel
docs/io_list.csv: 5 сигналов, 3 устройства — 2 ошибки
```

- **Строка** — номер строки в файле, как в Excel: заголовок — строка 1 (если над ним титул — номер
  считается от начала листа). Колонка — буква, как в Excel, и заголовок из файла.
- **Код** — правило; все 74 правила с уровнем и группой — `iolistgen schema --section rules`,
  с примерами — [schema.md, раздел 11](schema.md#11-проверки).
- **Уровень:** `[ошибка]` — генерация невозможна; `[предупреждение]` — генерация идёт (с `--strict` —
  нет).
- **Отчёты:** `--report md` — Markdown для pull request ([пример](io_list_broken.validation.md)),
  `--report html` — одна страница без внешних ресурсов с фильтром «ошибки/предупреждения» и поиском
  по тегу, `--report both` — оба; `--format json` — для CI и редакторов, `-q` — только итог. Время
  прогона в отчёт не пишется: повторная проверка того же перечня даёт тот же отчёт побайтно.
- **Коды выхода:** 0 — ошибок нет; 1 — в перечне ошибки (с `--strict` — и предупреждения); 2 —
  неверные аргументы, ошибка в `iolistgen.toml`, файла нет или формат не `.csv`/`.xlsx`.

**Частые ошибки**

| Код | Что обычно случилось | Что сделать |
|---|---|---|
| IOL001 | CSV сохранён в cp1251 | «CSV UTF-8» или `--encoding cp1251` |
| IOL003 | в заголовке нет обязательной колонки | добавить `tag`, `description`, `signal_type`, `device_type` или `dev_no` (или синоним) |
| IOL005 | колонка с незнакомым заголовком (предупреждение) | переименовать, добавить синоним в `[input] column_aliases` или в `[input] ignore_columns` |
| IOL007 | «4,5,1» вместо числа; дата Excel вместо `1.5` | исправить значение; числовой колонке в Excel дать числовой формат |
| IOL102, IOL103 | кириллица в теге («Е» вместо «E»); дубль тега без учёта регистра | латинские буквы; уникальные теги |
| IOL104 | тег не по правилу имён (по умолчанию `LT101`, `P101_RUN`) | переименовать или задать своё правило `[naming] tag_regex` |
| IOL204, IOL208, IOL209 | шкала min ≥ max; уставки не по возрастанию LL < L < H < HH; уставка вне шкалы | исправить шкалу или уставки — иначе ФБ отклонит настройки при старте |
| IOL308 | у устройства нет обязательной роли: ПЧ без `SPEED_REF`, задвижка без «Закрыть» | добавить строку с ролью |
| IOL311 | два устройства с одним `dev_no` | уникальный номер; новым устройствам — больше прежних |
| IOL412 | адреса Modbus пересекаются с учётом длины типа (`REAL` занимает два регистра) и битов | сдвинуть адрес |
| IOL502, IOL503 | опечатка в имени поля `params`, значение не того типа | исправить; при опечатке подсказка называет ближайшее поле |
| IOL507 | итоговые настройки не пройдут `CheckConfig` ФБ (гистерезис шире шкалы, `UINT` без шкалы отсчётов) | исправить параметры по тексту сообщения |
| IOL601 | два сигнала на одном канале модуля | проверить `io_module` и `io_channel` |

Витрина почти всех групп ошибок — [`examples/broken/io_list_broken.csv`](../examples/broken/io_list_broken.csv)
(в колонке «Пояснение» сказано, что сломано) и [отчёт по ней](io_list_broken.validation.md).

**Ослабить правило** проекта можно в `iolistgen.toml`:

```toml
[severity]
IOL104 = "warning"   # правило тегов — пока предупреждение
IOL414 = "off"       # Modbus TCP: адреса слейвов 248…255 допустимы
```

Структурные правила (тег, роль, тип устройства, адрес Modbus — в справочнике «Ослабить: нет»)
понизить нельзя: `iolistgen` откажет с кодом выхода 2 — без этих данных модель перечня не строится.

## 7. Генерация

```bash
iolistgen generate docs/io_list.csv --out . --strict
```

Перед генерацией перечень проверяется ещё раз; при ошибках — `генерация отменена: в перечне N
ошибок`, код выхода 1, ни один файл не записан. Генераторы работают в памяти, и файлы пишутся,
только если все отработали без ошибок. Повторный запуск без правок перечня — `изменено: 0`: файл
перезаписывается, только если изменилось содержимое; пересохранение книги Excel без правок тоже
ничего не меняет.

| Генератор | Файлы при `--out .` | Что внутри |
|---|---|---|
| `st-codesys` | `src/GVLs/Generated/`: `GVL_IO`, `GVL_DevIdx`, `GVL_Hmi`, `GVL_Persist` (`.pvl.st`), `GVL_CfgProject`, `GVL_Devices`; `src/POUs/Generated/`: `PRG_Devices`, `PRG_ApplyProjectCfg` | каналы и регистры, номера устройств, команды HMI, настройки и Retain (Persistent Variables), уставки проекта, экземпляры `PL.FB_*`, вызовы с привязками, «применить уставки проекта» |
| `modbus-map` | `docs/modbus_master_map.csv`, `docs/modbus_slave_map.csv`, `docs/modbus_map.md` | master — сигналы MB перечня; slave — блоки состояний устройств для SCADA |
| `scada-csv` | `scada/scada_tags.csv`, `scada/scada_alarms.csv` | теги с путями переменных ПЛК и узлами OPC UA, шкалами, уставками; тревоги |
| `alarm-list` | `docs/alarms.csv` | номер `dev_no · 10 + слот`, код, приоритет, текст, причина, последствие, действие оператора |
| `docs-table` | `docs/signal_list.md` | «Перечень сигналов» с колонкой «Переменная ПЛК» |

- Только часть генераторов — `--only st-codesys,modbus-map`; опция — `--set <генератор>.<опция>=<значение>`
  или `[generators.<генератор>]` в `iolistgen.toml`; все опции с умолчаниями — `iolistgen generate --list`.
  Пример: другое пространство имён библиотеки в проекте — `--set st-codesys.namespace=…`.
- Свои шаблоны кода — опция `template_dir`: файл с тем же именем перекрывает шаблон пакета.
- Свои данные в `GVL_Persist` (задание оператора, уставки станции) — опция `st-codesys.persist_extra`
  ([GENERATORS.md](GENERATORS.md#данные-приложения-в-gvl_persist-persist_extra)).
- Свой генератор — плагин с точкой входа `iolistgen.generators` ([PLUGINS.md](PLUGINS.md)).

**Сверка `GVL_Persist`.** Если в каталоге вывода уже есть `GVL_Persist.pvl.st`, генератор сравнивает
с ним новый и предупреждает: «тип изменился», «переменная удалена», «dev_no был у …», «новое
устройство получило dev_no меньше прежнего», «порядок данных приложения изменился». Каждое такое
предупреждение значит потерю сохранённых в ПЛК уставок, наработки или данных приложения после
загрузки. С `--strict` оно отменяет запись файлов — так генерацию стоит запускать и в CI.

## 8. Подключение к проекту из plc-repo-template

Шаги 1–4 выполнены 19.10.2026 в чистом клоне plc-repo-template с перечнем из пяти строк
([README](../README.md#как-использовать-в-своём-проекте)). Шаги 5–7 — порядок, которым собран
пример КНС-1 в этом репозитории ([MANUAL_STEPS.md, раздел 9](MANUAL_STEPS.md#9-код-сгенерированный-iolistgen-в-проекте-codesys));
в проекте из шаблона они не запускались.

1. **Установить iolistgen** в окружение проекта:

   ```bash
   python -m pip install "git+https://github.com/kr0nsch/iolistgen.git@v0.2.0"
   ```

2. **Перечень, проверка, генерация** (разделы 2–7):

   ```bash
   iolistgen validate docs/io_list.csv --report html --out build/reports
   iolistgen generate docs/io_list.csv --out . --strict
   ```

   Код ложится в раскладку шаблона (`src/GVLs/Generated/`, `src/POUs/Generated/`, папка проекта
   CODESYS `Generated`), заголовки POU проходят линтер шаблона.

3. **Линтер шаблона:** `python tools/check/st_lint.py --strict` — для пяти строк перечня и примера
   шаблона `st_lint: файлов 70, ошибок 0, предупреждений 0`.

4. **iec_checker.** По сгенерированному `PRG_Devices` он выдаёт одну находку `PLCOPEN-L17`: IF без
   ELSE в обработке команды «применить уставки проекта». Пока она не обоснована, падают шаг
   iec_checker и тест `tools/tests/test_run_iec_checker.py` шаблона. Добавьте в
   `tools/check/iec_checker_allow.toml` запись (та же — в [этом репозитории](../tools/check/iec_checker_allow.toml)):

   ```toml
   [[allow]]
   id = "PLCOPEN-L17"
   file = "src/POUs/Generated/PRG_Devices/PRG_Devices.impl.st"
   reason = "Команда HMI «применить уставки проекта» не пришла — делать нечего; пустая ветка ELSE в сгенерированном коде только добавит шум"
   ```

   С ней `run_iec_checker.py --tests` — `необоснованных 0`, pytest шаблона проходит. RuSTy шаблона
   (`tools/check/run_rusty.py`) по такому `src/` не пройдёт: типов `PL.*` без библиотеки он не знает
   (необязательное задание CI шаблона); компиляцию сгенерированного кода без CODESYS проверяет
   раздел 10.

5. **Библиотека plc-process-lib** — в `tools/codesys/config.json`: запись в `libraries` и ключ в
   `library.libraries` (подключает библиотеку ко всем режимам и к `cds.py check`). Запись этого
   репозитория:

   ```json
   "libraries": {
     "plc-process-lib": {
       "namespace": "PL",
       "title_contains": "plc-process-lib",
       "company": "plc-portfolio",
       "version": "1.0.0.0",
       "build_from_repo": {"env": "PL_REPO", "default": "../plc-process-lib"},
       "install_from": {"env": "PL_LIBRARY", "default": null}
     }
   },
   "library": {"libraries": ["standard", "plc-process-lib"]}
   ```

   Если версии 1.0.0.0 нет в репозитории библиотек CODESYS, `cds.py` соберёт её в клоне
   `../plc-process-lib` (тег `v1.0.0`) или поставит из файла `.library` (`PL_LIBRARY`). Проверить без
   сборки — `python tools\codesys\cds.py deps --check`.

6. **Вызов и объект Persistent Variables.**
   - В `PRG_Main` (задача `MainTask` шаблона) вызвать `PRG_Devices();` после логики станции: логика
     пишет входы автоматики устройств и вызывает ПИД-регуляторы до вызова устройств. Пример —
     [`src/POUs/PRG_Main/PRG_Main.impl.st`](../src/POUs/PRG_Main/PRG_Main.impl.st).
   - `python tools\codesys\cds.py import` создаёт проект из `src/`, кроме `GVL_Persist`: объект
     Persistent Variables скрипт CODESYS 3.5.17 не создаёт, о файле `GVL_Persist.pvl.st` будет
     предупреждение. Создать его один раз: в IDE открыть `build\<имя>.project`, «Приложение →
     Добавить объект → Persistent Variables», имя `GVL_Persist`, сохранить, закрыть IDE и выполнить
     `python tools\codesys\cds.py import --force`. Либо скопировать из этого репозитория
     `tools_project/codesys_pvl.py` и `tools_project/codesys_pvl_cds.py` и запустить
     `python tools_project\codesys_pvl.py` (для тестового проекта — с `--tests`). Второй файл —
     скрипт CODESYS на IronPython 2.7: `ruff check` шаблона выдаёт по нему 7 замечаний, `ruff format
     --check` — ещё одно, пока в
     `pyproject.toml` нет таких же исключений для `tools_project/*_cds.py`, как в
     [pyproject.toml](../pyproject.toml) этого репозитория (`[tool.ruff.format] exclude` и
     `[tool.ruff.lint.per-file-ignores]`).
   - Не использовать `cds.py import --clean` и `cds.py roundtrip`: в пересозданном проекте объекта
     Persistent Variables нет.

7. **Сборка и привязки.** `python tools\codesys\cds.py build` — ошибки компилятора приходят с файлом
   и строкой раскладки (`src/POUs/Generated/PRG_Devices/PRG_Devices.impl.st:42`). Дальше вручную, в
   IDE ([MANUAL_STEPS.md, 9.5–9.6](MANUAL_STEPS.md#95-каналы-модулей-modbus-адаптеры-пч)):
   - каналы модулей — в дереве устройств, I/O Mapping → «Map to existing variable» →
     `Application.GVL_IO.<переменная>`; какой канал к какой переменной — комментарий в
     `GVL_IO.gvl.st` и колонка «Переменная ПЛК» в `docs/signal_list.md`;
   - Modbus — мастер и слейвы по `docs/modbus_master_map.csv`; 32-битные значения с порядком слов и
     переменные состояния обмена `GVL_IO.xMbOk_<линия>_S<слейв>` пишет слой Modbus приложения;
   - ПЧ — адаптер приложения разбирает слово состояния и пересчитывает скорость;
   - SCADA — символьная конфигурация (`GVL_Devices`, `GVL_Hmi`, для сигналов `AUX` — `GVL_IO`) и
     импорт `scada/scada_tags.csv`; номер пространства имён и имя устройства в узлах OPC UA сверить
     обзором сервера (опции `scada-csv.opcua_namespace`, `scada-csv.opcua_device`).

Проект без шаблона: файлы `.st` раскладки описаны в [LAYOUT.md](LAYOUT.md) — объявление и тело
каждого объекта можно перенести в IDE вручную; такой путь не проверялся.

## 9. Цикл изменения перечня

1. Правка `docs/io_list.csv` (или книги).
2. `iolistgen validate docs/io_list.csv` — до нуля ошибок.
3. `iolistgen generate docs/io_list.csv --out . --strict` — печатает, какие файлы записаны, а какие
   без изменений; предупреждения сверки `GVL_Persist` читать до загрузки в контроллер.
4. `git diff` — в диффе только то, что следует из правки перечня.
5. `python tools\codesys\cds.py build`: импорт меняет только объекты с изменившимся текстом, объекты
   удалённых из перечня устройств удаляет из проекта вместе с файлами.
6. Коммит перечня и сгенерированных файлов вместе.

## 10. Проверка сгенерированного ST без CODESYS

Скрипт из клона iolistgen генерирует код по перечню в `build/st_check/` и проверяет его линтером,
склейкой и компилятором RuSTy по заглушке plc-process-lib (`tests_support/pl_stub/`):

```bash
python tests_support/check_generated_st.py --list <путь>/docs/io_list.csv
```

Увидите для перечня из пяти строк: `st_lint: без замечаний; assemble: ок; RuSTy: без ошибок` и
`check_generated_st: случаев 1, с ошибками 0`. Нужен RuSTy v1.0.6 (где взять —
[tools/README.md](../tools/README.md#checkrun_rustypy--проверка-rusty)); без него — `--no-rusty`
(только линтер и склейка) или `--optional` (нет RuSTy — предупреждение). Это проверка синтаксиса и
типов против заглушки, а не сборка в CODESYS.
