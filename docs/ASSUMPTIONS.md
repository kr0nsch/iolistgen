# Допущения и решения

Сюда записываются решения, принятые без полной информации, и их обоснование. Если допущение
подтвердилось или опровергнуто — пометьте это здесь, а не удаляйте запись.

Статусы: **принято** — решение действует; **проверить** — нужна сверка с источником или прогоном;
**подтверждено** — проверено, указано чем.

## iolistgen: схема перечня и проверка

| № | Допущение | Статус | Обоснование / где проверить |
|---|---|---|---|
| E1 | Схема перечня — по контракту plc-process-lib 1.0.0 (`API.md`, раздел 20): колонки `device`, `dev_no`, `role`, `params`, `link_power`, `link_fb` и таблица ролей 20.2 | подтверждено | Контракт библиотеки и пункт O4 журнала ревью API. С версии 0.2.0 каталог (`catalog.py`, `fbapi.py`) сверяется не с текстом контракта, а с исходниками выпуска 1.0.0 скриптом `tests_support/check_library.py` (перечисления, Cfg с умолчаниями, Cmd/Sts/Retain, входы и выходы ФБ, константы `GVL_Const`, полнота); код КНС-1 собран с библиотекой в CODESYS 3.5.17.30 (19.10.2026) |
| E2 | Необязательные колонки сверх контракта: `dev_desc`, `io_module`, `io_channel`, `mb_link`, `mb_slave`, `mb_bit`, `mb_order` | принято | Слейв и линия нужны, чтобы искать пересечения адресов внутри слейва; бит — для BOOL в регистре; порядок слов — для 32/64-битных значений; модуль и канал — документация и поиск двух сигналов на одном канале; описание устройства — тексты тревог и SCADA |
| E3 | Адрес Modbus в перечне — адрес PDU с нуля; нумерация с единицы — настройка `[modbus] address_base = 1`; номера вида 40001 не поддерживаются | принято | Так адрес задаётся в конфигураторе Modbus CODESYS («смещение»); одно соглашение исключает ошибку «±1» |
| E4 | Пустой порядок слов 32/64-битного значения — HL с предупреждением IOL408, если не задан `[modbus] default_word_order` | принято | Протокол Modbus — big-endian, но у приборов встречается LH; молчаливое умолчание прятало бы ошибку перепутанных слов |
| E5 | Пересечение адресов ищется внутри «линия, слейв, пространство» с учётом длины типа и битов; чтение и запись одного регистра хранения — тоже пересечение | принято | Два сигнала на одной ячейке памяти — почти всегда ошибка копирования; биты одного регистра (`mb_bit`) — не пересечение |
| E6 | Правило тегов по умолчанию `^[A-Z]{1,4}[0-9]{1,4}[A-Z]?(_[A-Z0-9]+)*$`, устройств — `^[A-Z]{1,4}[0-9]{1,4}[A-Z]?$` | **проверить** | Буквенные коды в духе ГОСТ 21.208-2013 (LT, PT, FT, LS) и номер позиции; сверить с проектным стандартом обозначений и принятой нумерацией позиций. Правило — в `iolistgen.toml` |
| E7 | Предел длины имени устройства — 24 символа (`[naming] max_device_length`) | **проверить** | Имя входит в коды тревог `<DEV>.<SUFFIX>` и теги SCADA; сверить с ограничениями выбранной SCADA |
| E8 | Дискретные роли двигателя и арматуры (`RUN_FB`, `FAULT`, `LOCAL`, `ZSO`, …) — только DI, сигнал MB для них не допускается | принято | Контракт 20.2. Удалённые модули ввода-вывода по Modbus (например, ОВЕН МВ110) — предложение к следующей версии контракта |
| E9 | Пустая роль единственной строки AnalogInput или DigitalInput — главная роль (PV или IN) | принято | Контракт требует роль; у одной строки AI/DI она однозначна. Во второй строке без роли — ошибка IOL304 |
| E10 | Неизвестная колонка — предупреждение IOL005, значения доступны генераторам (`Signal.extra`); колонки из `[input] ignore_columns` не читаются | принято | В перечнях почти всегда есть «№ п/п», «Примечание»; генератору документации они полезны |
| E11 | Строка с дублем тега не входит в устройство | принято | Иначе один дубль давал бы цепочку следствий: «роль повторяется», «разные dev_no» |
| E12 | `alarm_priority = None` у AnalogInput выключает все четыре предела | принято | Контракт: H и L — на ступень ниже значения колонки; для None ступени ниже нет |
| E13 | В `params` значения — литералы ST (`T#30S`); в колонках задержек — секунды или литерал TIME | принято | Контракт 20.1 («литерал ST»); колонки задержек названы с единицами (`delay_on_s`) |
| E14 | Явные `xFbUsed`, `xZsoUsed`, `xZscUsed`, `xTorqueUsed`, `eType`, `eInput` в `params` перекрывают выводы из состава устройства, если не противоречат строкам перечня (иначе IOL509) | принято | Вывод генератора — удобное умолчание, а не запрет; противоречие (`xZsoUsed = TRUE` без концевика) ФБ превратил бы в отказ «не открылась» |
| E15 | MotorVfd: при `stVfd.xFbFromComm = TRUE` (умолчание) `xFbUsed` остаётся TRUE без строки `RUN_FB`; строка `RUN_FB` при этом — предупреждение IOL315 | принято | `API.md` 14.2: ОС «в работе» берётся из слова состояния ПЧ, вход `xFbRun` не используется |
| E16 | PV по Modbus целого типа с явным `eInput=Eng` допустим (значение уже в инженерных единицах); без него — `eInput := Raw` и обязательны `rRawLo_cnt`, `rRawHi_cnt` | принято | Контракт 20.3 задаёт умолчание Raw; приборы, которые отдают целое уже в единицах (°C), встречаются |
| E17 | В отчёты не пишется время прогона, только SHA-256 перечня и версия | принято | Отчёт детерминирован: дифф показывает изменение перечня, а не времени |
| E18 | Пакет поддерживает Python 3.10+ (`tomli` для 3.10); инструменты шаблона — 3.11+ | принято | Требование к проекту 07; CI проверяет пакет на 3.10, 3.12 и 3.13 |
| E19 | HTML-отчёт: системные шрифты, цвет — только для уровней сообщений (ISA-101), светлая и тёмная тема по настройке системы | принято | Один файл без внешних ресурсов открывается где угодно и годится для скриншота |
| E20 | Роль `AUX` — расширение схемы iolistgen сверх контракта 20.2: сигнал без входа и выхода ФБ, в составе устройства (сколько угодно строк) или отдельной строкой без `device` и `device_type` («простой» сигнал) | принято | Ревью: лампы, сирены, реле, регистры, которые читает адаптер (код аварии ПЧ), и резервные каналы иначе записывались комментариями и выпадали из `GVL_IO`, карты Modbus (и проверки пересечений адресов), SCADA и документации. Библиотеку не затрагивает: экземпляра, Cmd, Cfg, тревог у AUX нет. Предложить в контракт plc-process-lib (раздел 20.2) |
| E21 | Структурные правила (тег, тип сигнала, роль, тип и номер устройства, адрес Modbus — список `STRUCTURAL_RULES` в `iolistgen/diagnostics.py`) не ослабляются в `[severity]`: попытка — ошибка настроек | принято | Ревью: `IOL201 = "off"` при пустом описании давал `AssertionError` вместо сообщения, `IOL302 = "off"` — модель без типа устройства. Проектные правила и зеркало `CheckConfig` ослабить можно; тест ослабляет каждое из них на перечне, где оно срабатывает, и строит модель и имена ПЛК |
| E22 | Адрес слейва 0 — отдельное правило IOL416 (ошибка, ослабляется); 256 и больше — IOL413 (структурное) | принято | В Modbus RTU адрес 0 широковещательный (ответа на чтение нет), а в Modbus TCP Unit ID 0 — обычный адрес; тип линии в перечне не задан, поэтому решает проект через `[severity] IOL416` |
| E23 | SHA-256 перечня — по содержимому таблицы (строка заголовка и строки данных, тексты ячеек), а не по байтам файла | принято | Ревью: пересохранение XLSX без правок меняло байты архива (время в `docProps`), а с ними — заголовки всех 17 сгенерированных файлов и текст объектов в CODESYS. Титул, пустые строки и комментарии на хеш не влияют |
| E24 | XLSX: объединение по вертикали ниже заголовка действует в каждой строке (в первой колонке объединения); строка, где заполнено только объединение по горизонтали, — подзаголовок и пропускается | принято | Так читает перечень человек: «Устройство» и «Группа HMI» на все строки насоса — частая вёрстка. Раньше строки насоса без `device` становились отдельными «устройствами» с ошибкой «не задан тип» |
| E25 | Числа из XLSX округляются до 15 значащих цифр; в числах принимаются минус U+2212 и тире перед цифрой, разряды через пробел, неразрывный и узкий неразрывный пробел; ячейка из одних тире в числовой колонке — «нет значения»; задержка — и ячейкой времени Excel | принято | Excel хранит до 17 значащих цифр, а показывает 15: значение формулы `0,1+0,2` иначе попадало бы в ST как `0.30000000000000004`. Минус U+2212 приходит из Word, PDF и паспортов приборов и выглядит как «-»; «—» в таблицах означает «не задано» |
| E26 | Заголовок колонки сравнивается и по части до первой запятой или скобки: «HH, м», «Уставка HH, ед. изм.», «Адрес регистра (PDU)» | принято | Единицы в заголовке — частая вёрстка перечня; без этого колонка считалась неизвестной (IOL005) и её значения не проверялись |
| E27 | Имя линии Modbus, из которого не получается идентификатор ST, — предупреждение IOL417 (имена переменных состояния обмена тогда `L1`, `L2`… по алфавиту линий) | принято | Новая линия с кириллическим именем сдвинула бы имена переменных, привязанных в дереве устройств |
| E28 | Значения из списка (тип сигнала, роль, тип устройства, тип данных и порядок слов Modbus, приоритет) сравниваются без учёта регистра, с заменой кириллических букв-двойников на латинские и по первому слову, если после значения стоит пояснение | принято | «АI», набранное в русской раскладке, и «AI 4–20 мА» однозначны; неизвестное первое слово по-прежнему ошибка с подсказкой. В тегах кириллица-двойник остаётся ошибкой (IOL102): тег становится именем переменной |
| E29 | ПИД-регулятор (`Pid`) в перечне — строка устройства без `signal_type` и `role`; в составе — только сигналы `AUX`; `range_min`/`range_max` задают диапазон PV (`rPvMin_eu`, `rPvMax_eu`), а также пределы задания по умолчанию (выводятся, перекрываются в `params`); без диапазона — предупреждение IOL213 | принято | Решение I-13 библиотеки (вариант A ревью): «устройство без ролей ввода-вывода: строка перечня с `device_type = Pid`, `dev_no`, параметрами Cfg» (CONSUMERS G3). Входы ПИД — значения других устройств, а не сигналы, поэтому ролей нет; псевдороль или фиктивный сигнал дали бы лишнюю переменную `GVL_IO`. Задание вне шкалы датчика бессмысленно — отсюда пределы задания по диапазону PV; диапазон по умолчанию 0…100 для уровня в метрах дал бы неверную нормировку ошибки, но ФБ его принимает, поэтому это предупреждение, а не ошибка |
| E30 | Строка без типа сигнала (кроме строки устройства Pid) — ошибка IOL202 «тип сигнала не задан» | принято | До 0.2.0 пустой `signal_type` не проверялся, и такая строка ломала построение модели (утверждение в `validate.py`); IOL202 — структурное правило, как и неизвестный тип сигнала |

## iolistgen: генераторы

| № | Допущение | Статус | Обоснование / где проверить |
|---|---|---|---|
| G1 | Каналы модулей в `GVL_IO` — переменные без `AT %I…/%Q…`, привязка — в дереве устройств («Map to existing variable») | принято | В перечне — имена модулей и номера каналов, а не адреса МЭК; адреса зависят от дерева устройств и таргета ПЛК210. Код не меняется при перестановке модулей, те же переменные пишет модель в симуляции (проект 02) |
| G2 | Значения Modbus (ПЛК — master) объявлены в `GVL_IO` в типе прибора (INT, REAL, WORD, BOOL); пишет и читает их слой Modbus (конфигуратор или код приложения), он же собирает 32/64-битные значения по порядку слов | **проверить** | Задача генератора — имена и карта обмена; разбор регистров зависит от конфигуратора. Привязку канала Modbus к переменной INT/REAL в конфигураторе 3.5.17 — сверить; при отказе — массив WORD и разбор в слое Modbus |
| G3 | Состояние обмена со слейвом — `GVL_IO.xMbOk_<линия>_S<слейв>` (TRUE — исправен); AI и DI по Modbus без строки `CHF` получают `xChannelFault := NOT xMbOk_…` | принято | Контракт 20.2 для AI («у MB — статус обмена со слейвом»); для DI по Modbus — тот же смысл. Начальное FALSE: без слоя Modbus значение недостоверно |
| G4 | Переменные адаптера ПЧ: `x<DEV>_CommOk`, `x<DEV>_VfdRun`, `x<DEV>_VfdReady`, `x<DEV>_VfdFault`, `r<DEV>_SpeedAct_pct`, `r<DEV>_SpeedRef_pct`, при пуске по Modbus — `x<DEV>_VfdQRun`, `x<DEV>_VfdQReset`; задание AO и факт AI ПЧ тоже идут через адаптер | принято | Имена — по примеру контракта 20.6; роли `SPEED_REF`/`SPEED_ACT` (MB, AO, AI) — «через адаптер» (20.2): шкала ПЧ у разных моделей разная |
| G5 | Константы `GVL_CfgProject` названы как переменные `GVL_Persist` (`st<DEV>Cfg`), правило STL007 для них подавлено `lint:allow` с причиной | принято | Контракт 18.3, правило 2. STL007 требует UPPER_SNAKE_CASE у любой константы, включая структуры; переименование разошлось бы с контрактом |
| G6 | «Применить уставки проекта» — `PROGRAM PRG_ApplyProjectCfg` (копирование Cfg), команда HMI — импульс `GVL_Hmi.xApplyProjectCfg`, его обрабатывает и сбрасывает `PRG_Devices` | принято | Контракт 18.3 называет процедуру и команду HMI, но не форму. PROGRAM без входов вызывается из `PRG_Devices` и из логики станции; FUNCTION без входов в 3.5.17 не проверялась |
| G7 | `GVL_Persist` — без `{attribute 'qualified_only'}` (как в примере контракта 18.3), все обращения в сгенерированном коде квалифицированы | принято | Действие атрибута в объекте Persistent Variables не проверялось; одноимённые константы `GVL_CfgProject` закрыты своим `qualified_only` |
| G8 | Порядок вызовов в `PRG_Devices`: устройства, на которые ссылаются `link_*`, затем остальные по `dev_no`; входы, которых нет в перечне, не передаются (кроме `xChannelFault`) | принято | Контракт 20.6 («вызывает раньше ссылающихся»), R5: входы автоматики пишет логика станции, непереданный вход хранит последнее значение |
| G9 | Карта slave: блоки `stSts` подряд по `dev_no` (опция — адрес по `dev_no · шаг`), холдинг-регистры, порядок слов 32-битных полей LH | **проверить** | Открытый вопрос O5 контракта. LH — копия памяти структуры на ПЛК с прямым порядком байт; способ копирования (функция копирования памяти таргета 3.5.17) и ожидание SCADA — сверить |
| G10 | Идентификатор узла OPC UA — `ns=4;s=\|var\|<устройство>.Application.<путь>`, по умолчанию устройство «CODESYS Control Win V3» | **проверить** | Номер пространства имён и имя устройства зависят от рантайма и версии; сверить обзором сервера (UaExpert) на Control Win и на ПЛК210, задать опциями `scada-csv` |
| G11 | В список тревог не входят слоты с приоритетом `None` и слоты, условие которых при составе устройства не возникает (без ОС, концевика, муфты, строки `FAULT`/`CHF`/`POS_FAULT`, выход за диапазон без NE 43) | принято | Разделы 11–16 контракта: условия слотов. Опция `only_possible = false` возвращает полный список |
| G12 | Формата импорта тегов MasterSCADA 4D нет — заготовка плагина без вывода, вместо него `scada-csv` и карта slave | принято | Справка IEK Digital (2026-10-16): OPC UA — обзор сервера; xlsx каналов Modbus — «совместимый с экспортом», раскладка не описана (docs/GENERATORS.md, раздел «SCADA») |
| G13 | CSV генераторов начинаются со строк `# AUTO-GENERATED …`; для импорта без комментариев — опция `comment_header = false` | принято | Требование «у каждого сгенерированного файла заголовок»; часть SCADA строк-комментариев не принимает |
| G14 | Слова «TODO», «FIXME» и «lint:allow» из текста перечня попадают в комментарии ST строчными буквами | принято | Иначе описание сигнала сломало бы st_lint (STL004, STL012) в сгенерированном коде |
| G15 | `iolistgen generate` пишет файлы, только если все генераторы отработали без ошибок (с `--strict` — и без предупреждений); два генератора на один файл — ошибка до записи | принято | Ревью: сбой генератора или плагина после `st-codesys` оставлял новый ST рядом со старыми картами обмена; предупреждение сверки `GVL_Persist` («тип изменился» — потеря уставок) не останавливало CI с `--strict` |
| G16 | Сигнал AUX: переменная `GVL_IO` по типу сигнала, в вызове устройства — комментарий, тег SCADA только для чтения (`GVL_IO` в символьной конфигурации), простые сигналы — в конце `scada_tags.csv` и в разделе «Сигналы без ФБ» перечня | принято | Выход AUX пишет код приложения; запись выхода из SCADA мимо логики не предусмотрена |
| G17 | У сигналов, которые обрабатывает адаптер ПЧ (слова ПЧ, задание и факт скорости, в том числе AO/AI), комментарий в `GVL_IO` заканчивается словами «адаптер ПЧ» | принято | Ревью: переменная аналогового задания ПЧ (`rP202_REF`) не встречается в `PRG_Devices` и выглядела непривязанной |

## Семантика F_Clamp

_Функция примера шаблона, удалена в 0.2.0; раздел оставлен для истории решения C1._

`F_Clamp(rValue, rLow, rHigh)` возвращает `rValue`, ограниченное отрезком между границами.

- Границы включаются: `F_Clamp(rLow, rLow, rHigh) = rLow`, `F_Clamp(rHigh, rLow, rHigh) = rHigh`.
- **Если `rLow > rHigh`, границы меняются местами.** Результат всегда лежит между двумя заданными
  числами и не зависит от порядка аргументов. Альтернативы были такие: вернуть `rLow` или повторить
  поведение `LIMIT` (`MIN(MAX(IN, MN), MX)` при `MN > MX` всегда даёт `MX`). Обе дают результат на
  одной из границ при любом входе, и ошибку конфигурации легко не заметить. Функция с результатом
  `REAL` не может сообщить об ошибке, поэтому выбрано поведение без скачков.
- Вырожденный отрезок `rLow = rHigh` — результат всегда равен границе.
- NaN не обрабатывается: при `rValue = NaN` результат — NaN. Достоверность измерения проверяется
  до вызова (NAMUR NE 43 — в ФБ аналогового входа).
