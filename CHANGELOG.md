## [Unreleased]

### Added

- Пакет `iolistgen` 0.1.0 (Python 3.10+): проверка перечня сигналов (CSV, XLSX) по схеме из
  контракта plc-process-lib (раздел 20) — строка — сигнал, устройство — группа строк с ролями;
  `docs/schema.md`, модели pydantic v2.
- 73 правила проверки (55 ошибок, 18 предупреждений): дубли тегов без учёта регистра, шкалы и
  уставки, единицы, правило имён из `iolistgen.toml`, состав устройств и роли, пересечения
  адресов Modbus с учётом длины типа и битов, функции и направления, каналы модулей, параметры
  Cfg с типами по DUT библиотеки и зеркало `CheckConfig` ФБ. В каждом сообщении — файл, строка,
  колонка, что не так и как исправить.
- Отчёты Markdown и самодостаточный HTML; вывод JSON.
- Архитектура генераторов: протокол `Generator`, опции, идемпотентная запись, реестр встроенных
  генераторов и плагинов (точки входа `iolistgen.generators`).
- Команда `iolistgen`: `validate`, `generate`, `schema`; справка по-русски; установка `pipx install .`.
- Генератор `st-codesys`: ST в раскладке шаблона по контракту plc-process-lib (разделы 1, 18.3,
  20.6) — `GVL_IO` без адресов `AT` (каналы модулей, значения Modbus, состояние слейвов, переменные
  адаптеров ПЧ), `GVL_DevIdx`, `GVL_Hmi`, `GVL_Persist` (Persistent Variables по возрастанию
  `dev_no`), `GVL_CfgProject`, `GVL_Devices`, `PRG_Devices` (все `VAR_IN_OUT`, порядок по `link_*`),
  `PRG_ApplyProjectCfg`; шаблоны Jinja2, опции `time_source`, `alarm_sink`, `folder`,
  `template_dir`; сверка с прежним `GVL_Persist`.
- Генераторы `modbus-map` (карта master и slave по раскладке `stSts`, CSV и Markdown), `scada-csv`
  (универсальный импорт тегов с путями ПЛК и узлами OPC UA, тревоги для SCADA), `alarm-list`
  (`docs/alarms.csv`); у `docs-table` — колонка «Переменная ПЛК».
- Заголовок сгенерированных файлов `AUTO-GENERATED by iolistgen <версия> — не редактировать;
  источник: …`, ключ `generate --timestamp`, предупреждения генераторов, `GenerationError` (код
  выхода 1).
- `iolistgen/fbapi.py`: входы и выходы ФБ, Cmd, Sts (смещения по контракту 4.6) и Retain библиотеки.
- Заглушка plc-process-lib `tests_support/pl_stub/` и проверка сгенерированного ST без CODESYS
  `tests_support/check_generated_st.py`: st_lint, сборка раскладки, RuSTy `plc --check`.
- Заготовка плагина MasterSCADA 4D `plugins/iolistgen-masterscada4d/`: документированного формата
  импорта тегов нет (справка вендора), генератор объясняет это и файлов не пишет.
- Эталонные файлы генераторов `pytests/golden/` по малому перечню `pytests/data/gen_fixture.csv`,
  тесты идемпотентности, обнаружения плагинов и отрицательный контроль RuSTy; `docs/GENERATORS.md`,
  раздел 9 `docs/MANUAL_STEPS.md`.
- Тесты pytest и hypothesis (поиск пересечений Modbus против полного перебора); задание CI
  `package`: Python 3.10, 3.12, 3.13, сборка и установка wheel, `pipx install .`.
- Раскладка исходников ST в `src/` и `tests/` и её формальный контракт `docs/LAYOUT.md`.
- Пример: `E_DeviceMode`, `ST_ExampleCmd`, `ST_ExampleSts`, `GVL_Const`, интерфейс `I_Resettable`,
  функция `F_Clamp`, `FB_Example` (метод `Acknowledge`, реализация `Reset`, свойство `Count`), `PRG_Main`.
- Тесты CfUnit (coUnit 1.2.0.0): наборы `FB_F_Clamp_Test` (7 тестов), `FB_Example_Test` (11 тестов:
  пороги и гистерезис, отказ и квитирование, режимы, ограничение параметров, счётчик, сброс через
  `I_Resettable`) и `PRG_Tests`.
- Инструменты: `tools/assemble.py`, `tools/check/` (линтер `st_lint.py`, запуск iec_checker и RuSTy),
  скрипты CODESYS Scripting в `tools/codesys/`.
- `tools/codesys/cds.py` — импорт, сборка, тесты coUnit в CODESYS Control Win V3 (пользовательский
  процесс), экспорт, roundtrip, JUnit и отчёт из консоли; настройки — `tools/codesys/config.json`.
  Проверено в CODESYS 3.5.17.30.
- Роль `AUX` — сигнал без входа и выхода ФБ (лампа, сирена, реле, регистр, который читает адаптер
  ПЧ, резервный канал): в составе устройства или простым сигналом без `device` и `device_type`.
  Генераторы дают ему переменную `GVL_IO`, строку карты Modbus с проверкой пересечений, тег SCADA и
  строку перечня; правило IOL317 — колонки устройства у простого сигнала.
- Правила IOL416 (адрес слейва 0 — широковещательный в Modbus RTU; для Unit ID 0 Modbus TCP
  ослабляется) и IOL417 (имя линии Modbus не даёт идентификатор ST).
- Чтение XLSX: объединённые по вертикали ячейки действуют в каждой строке, подзаголовки разделов
  (объединение через всю таблицу) пропускаются; задержки ячейкой времени Excel.
- Подсказки: строка устройства без `device` — какое устройство указать (по началу тега); строка-
  подзаголовок без `#` — как её оформить.
- Примеры (`examples/`): перечень КНС-1 проекта 02 — 58 сигналов, 29 устройств, теги по
  ГОСТ 21.208-2013, условная карта регистров ПЧ — в CSV и XLSX (`csv_to_xlsx.py`); синтетический
  перечень на 300 сигналов из генератора с зерном (`make_synthetic.py`), который покрывает все типы
  устройств, сигналов и ролей; витрина ошибок с отчётом `docs/io_list_broken.validation.md`.
- Замер времени `examples/benchmark.py`: проверка и генерация (медиана повторов), команда целиком
  в отдельном процессе, сведения о машине; отчёт `docs/benchmark.md` и итог в README.
- Тесты примеров `pytests/test_examples.py`: перечни без сообщений, XLSX = CSV, воспроизводимость
  синтетического перечня и книги XLSX, ожидаемое сообщение у каждой строки витрины ошибок, отчёт в
  `docs/` совпадает с выводом валидатора.

### Changed

- Генерация выполняется целиком или не выполняется: файлы всех генераторов пишутся только после
  того, как все отработали без ошибок; с `--strict` предупреждения генераторов (сверка
  `GVL_Persist`) отменяют запись и дают код выхода 1; два генератора на один файл — ошибка.
- SHA-256 перечня считается по содержимому таблицы, а не по байтам файла: пересохранение книги
  Excel без правок больше не переписывает все сгенерированные файлы.
- Структурные правила (тег, тип сигнала, роль, тип и номер устройства, адрес Modbus) нельзя
  ослабить в `[severity]`: колонка «Ослабить» в справочнике правил, `adjustable` в JSON схемы.
- Сирена, лампа, реле общей аварии и коды аварий ПЧ в перечне КНС — сигналы `AUX` вместо
  строк-комментариев; в синтетическом перечне — лампа и регистр кода аварии ПЧ.
- Комментарий у переменных `GVL_IO`, которые обрабатывает адаптер ПЧ, заканчивается словами
  «адаптер ПЧ»; `tests_support/check_generated_st.py` проверяет и примеры КНС-1 и синтетический,
  с `iolistgen.toml` рядом с перечнем.

### Fixed

- `[severity] IOL201 = "off"` (и другие структурные правила) при сработавшем правиле давал
  `AssertionError` вместо сообщения или модель с дырами; теперь такие настройки отвергаются с
  объяснением (код выхода 2).
- XLSX: объединённая ячейка «Устройство» на строки насоса читалась только в первой строке —
  остальные строки становились отдельными «устройствами» с ошибкой «не задан тип».
- Числа: минус U+2212 и тире перед числом (`−40` из паспорта прибора), разряды через узкий
  неразрывный пробел, «—» как «нет значения» в числовых колонках, ошибка формулы Excel названа
  ошибкой формулы; значения формул XLSX округляются до 15 значащих цифр (`0.3`, а не
  `0.30000000000000004` в ST).
- Заголовки с единицами после запятой или в скобках («HH, м», «Адрес регистра (PDU)»)
  распознаются; раньше колонка считалась неизвестной и не проверялась.
- PV или IN по Modbus со строкой `CHF`: `xChannelFault` учитывает и потерю обмена со слейвом
  (`CHF OR NOT xMbOk_…`) — раньше при потере связи замёрзшее значение оставалось достоверным.
- Каталог вместо файла перечня — понятное сообщение «это каталог», а не «файл не найден».
- Значения из списка (тип сигнала, роль, тип устройства…) с кириллической буквой-двойником
  («АI» в русской раскладке) или с пояснением после значения («AI 4–20 мА») больше не ошибка.
- Подсказки: нет строки заголовка — про `[input] column_aliases`; пустой тег резервного канала —
  про роль `AUX`.
- Колонка `alarm_priority` у `Motor` меняла и слот 6 «потеря связи с ПЧ» общей с `MotorVfd` Cfg:
  теперь меняются только слоты своего типа устройства.
- Отчёты проверки: найденный `iolistgen.toml` записывался в шапку абсолютным путём машины; теперь —
  путём относительно каталога перечня (`../iolistgen.toml`), отчёт в `docs/` одинаков на любой машине.
- Тесты coUnit: функции `TEST` и `TEST_FINISHED` вызываются с пространством имён (`coUnit.TEST(...)`) —
  без него сборка в CODESYS 3.5.17.30 давала ошибки C0046/C0035.
- CI GitHub Actions: ruff, mypy, pytest, сборка ST, линтер (`--strict`), iec_checker v0.4 (закреплён
  по размеру и SHA-256); необязательно — iec_checker `nightly` (образ закреплён по дайджесту) и RuSTy.
- Документы: архитектура, ручные шаги, допущения, отчёты статанализа и тестов, шаблоны ТЗ
  (ГОСТ 34.602-2020) и ПМИ.
